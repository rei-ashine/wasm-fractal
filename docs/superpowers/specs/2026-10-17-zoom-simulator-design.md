# 拡大できるフラクタル・シミュレーター 設計書

- 日付: 2026-10-17
- 対象: 個別のフラクタルのページ（Julia / Mandelbrot / Burning Ship / Celtic Mandelbrot）
- 状態: 設計確認済み。この設計書の確認のあと、実装計画を作る

## 1. 目的

個別のページを、拡大できるシミュレーターにする。用途は次の2つ。

- サイトを見に来た人が、スマホでも PC でも、ピンチ・ホイール・ドラッグで直感的に拡大・移動して探索を楽しめる。
- 中心座標、拡大率、最大反復回数、Julia 集合の定数 c を数値で指定して、細かく調べられる。

### 成功の条件

- iPhone と PC で、拡大・移動の操作に画像がすぐ追従し、手を止めると細かく描き直される。
- 表示中の場所が数値で分かり、数値を入力するとその場所へ移動する。
- ページを開いた直後の場所は今と同じ。ただし Mandelbrot と Julia は縦横比を正しくした分だけ上下の範囲が広がる（6章）。
- 操作をどう重ねても、最終的な画像は、同じ範囲を新しく描いた画像とピクセル単位で一致する（古い描画が残らない）。

### 範囲外

- URL での共有、画質（アンチエイリアス）の調整、状態の保存（ページを離れると最初の表示に戻る）。
- ギャラリーでの拡大操作。
- Rust/wasm の計算部分と Worker の仕組みの変更（`generate_fractal` はどんな範囲でも描ける）。
- Mac の Safari でのトラックパッドのピンチ（Safari 独自の GestureEvent）。2本指のスクロールはホイールとして拡大・縮小に使える。

## 2. 画面

上から順に並べる。表記はサイトに合わせて英語にする。

1. タイトルと数式（今のまま）。Julia のページでは「c = …」の行が現在の c を表示する。
2. キャンバス: 正方形。幅はコンテンツの幅いっぱいで、最大 600 CSS px。ギャラリーのような、マウスを乗せたときに浮き上がる効果は付けない。
3. 操作の行: `−`、`+`、`Reset` のボタンと拡大率の表示（例: `×1,250`、`×3.47e+9`、上限では `×9.40e+10 (max)`）。
4. 入力欄（フォーム）: `Center Re`、`Center Im`、`Zoom`、`Max iterations` と `Auto` のチェック。Julia のページだけ `c Re`、`c Im` も置く。Enter キーか `Go` ボタンで適用する。数字が読みやすいよう、入力欄は等幅フォントにする。
5. 状態表示: `Rendering...` / `Rendered in N ms`（N は描き直しの開始から本描きの完了まで）。

## 3. 操作

| 操作 | PC | タッチ |
|---|---|---|
| 拡大・縮小 | ホイール。カーソルの下の点を固定する | ピンチ。2本の指の中点を固定し、中点が動いた分だけ移動もする |
| 移動 | ドラッグ | 1本指のドラッグ |
| その点を2倍に拡大 | ダブルクリック | ダブルタップ |
| `+` / `−` | 中心を固定して2倍 / 2分の1 | 同じ |
| `Reset` | 表示範囲、`Auto` の反復回数、c を初期状態に戻す | 同じ |

- Pointer Events でマウス・タッチ・ペンをまとめて扱う。キャンバスに `touch-action: none` を付け、キャンバスの上ではブラウザのスクロールとページの拡大を止める。ページのスクロールはキャンバスの外で行う。
- 押したポインターは `setPointerCapture` で捕まえ、キャンバスの外へ出てもドラッグを続ける。マウスは左ボタンだけを扱う。
- 2本指から1本指に戻ったときは、残った指の位置を移動の基準にし直して、表示が飛ばないようにする。
- ホイールは `passive: false` で受け取って `preventDefault()` し、ページをスクロールさせない。倍率は `exp(-deltaY × 0.0015)`。`deltaMode` が行単位なら `deltaY` を 16 倍、ページ単位ならキャンバスの高さ倍に換算する。
- ダブルクリックとダブルタップは、Pointer Events で同じ方法で判定する。2回の押下が 300 ms 以内かつ 30 px 以内で、どちらの押下でもポインターが 6 px 以上動いていないとき。
- 今のページの「キャンバスをクリックすると描き直す」動作は、これらの操作に置き換える。
- 入力欄の数値は、キャンバスの操作に合わせて自動で更新する（画面の更新1回につき1回まで）。

## 4. 表示の状態と計算（`www/src/utils/viewMath.ts`）

### 状態

表示の状態は描く範囲 `{ x_min, x_max, y_min, y_max }` そのもので持つ。最初の状態は設定（`fractalConfig.ts`）の範囲と完全に同じ値にする。

- 中心と幅を持って範囲を計算し直す方式だと、Burning Ship の `-1.7 + 0.1` が `-1.6` ではなく `-1.5999999999999999` になる。Burning Ship の境界はわずかな差が反復の中で大きく広がるため、この差だけで 300×300 の画像の約3%のピクセルの色が変わった。範囲そのものを持てば、ギャラリーとページを開いた直後の範囲を今と完全に同じにできる。
- 範囲は正方形を保つ。縦と横には常に同じ倍率と移動量を使うので、丸め誤差の分を除けば正方形のままになる。
- 中心は `((x_min + x_max) / 2, (y_min + y_max) / 2)`、幅は `w = x_max - x_min`、拡大率は `zoom = w0 / w`（`w0` は最初の幅）。開いた直後が ×1。
- キャンバスの上端が `y_min` で、下に行くほど虚部が大きい（今と同じ向き）。

### 制限

- 縮小: 幅が 8 になるまで。8 は集合全体が入る広さで、Burning Ship は最初が ×1（幅 0.2）なので ×0.025 まで縮小できる。
- 移動: 中心は `|cx| ≤ 4`、`|cy| ≤ 4` の範囲に収める。
- 拡大の上限: 1ピクセルの幅 `w / n` が `K × ulp(max(|cx|, |cy|, 1))` を下回らないこと。`n` はキャンバスの一辺の物理ピクセル数、`ulp(m)` は m の大きさの倍精度の数の最小の刻み（`2^(floor(log2 m) − 52)`）。`K` の初期値は 8 にする。実装時に上限付近の描画を確かめて調整し、この設計書の値も更新する。
- 拡大・縮小の操作が制限を越えるときは、固定する点は保ったまま、倍率を制限ちょうどまで弱める。

### 最大反復回数

- `Auto`（初期設定）: `min(50000, round(base × (1 + max(0, log2(zoom)) / 4)))`。`base` は設定の初期値（Mandelbrot・Burning Ship・Celtic は 300、Julia は 1000）。例えば Mandelbrot は ×100万倍で約1,800回、×1兆倍で約3,300回になる。
- 手で入力したら `Auto` を外し、10〜100,000 の範囲でその値を使う。`Auto` に再びチェックを入れるか `Reset` を押すと自動に戻る。
- `Auto` の値は描き直しを始めるときの拡大率で決める（操作の途中では描かないので、途中の値は表示だけ）。

### 数値の表示

- 中心座標: 1ピクセルの幅が読み取れる桁数で表示する（小数点以下 `ceil(−log10(w / n)) + 1` 桁）。
- 拡大率: 100万未満は有効数字3桁で桁区切り付き（`×1,250`）、それ以上は指数表記（`×3.47e+9`）。入力欄は `1250` や `3.47e9` のような指数表記も受け付ける。

### 関数（すべて DOM に依存しない純粋関数）

- `rangeWidth(range)`、`rangeCenter(range)`、`zoomOf(range, w0)`
- `rangeFromCenter(cx, cy, zoom, w0)`: 入力欄の値から範囲を作る。
- `zoomAt(range, sx, sy, factor, size, limits)`: キャンバス上の点 (sx, sy) の複素数を固定して拡大・縮小する。`sx`、`sy`、`size`（キャンバスの一辺）は同じ単位（CSS px）。制限は上のとおり。
- `panBy(range, dx, dy, size, limits)`: 画像を (dx, dy) CSS px だけ指やマウスと同じ向きに動かす（範囲は逆向きに動く）。
- `clampRange(range, limits)`: 制限の内側に収める。
- `minWidthLimit(range, n)`: 上の精度の条件から決まる最小の幅。
- `autoMaxIter(base, zoom)`
- `previewTransform(from, to, size)`: `from` の範囲で描いた画像を `to` の範囲の表示に重ねるときの、左上の位置と一辺の大きさ。単位は `size`（キャンバスの一辺）と同じ。
- `formatCenter(value, pixelWidth)`、`formatZoom(zoom)`、`parseNumber(text)`

## 7. 描画の流れ（`FractalSimulator`）

1. **操作中のプレビュー:**
   - 操作のひと続きが始まったら、描きかけの描画を取り消す。そのうえで、今のキャンバスの画像とその範囲を、画面に出していない別のキャンバスに写し取る。
   - 操作で範囲が変わるたびに（画面の更新1回につき1回まで）、キャンバスを黒で塗る。そのあと、写し取った画像を `previewTransform` で新しい範囲の位置と大きさに合わせて描く。計算はしない。
2. **描き直しの開始:**
   - 開始するタイミング:
     - すべての指やマウスのボタンを離した直後
     - ホイールが 150 ms 止まったとき
     - `+`、`−`、`Reset`、`Go` を押したとき、最大反復回数が変わったとき（`Auto` をオンにしたときと、手で入力したとき）、c を変えたとき
     - キャンバスの物理ピクセル数が変わったとき（画面の回転やウィンドウの大きさの変更。`ResizeObserver` で検出する）
     - ページを開いたとき
   - 開始時には、写し取った画像を捨て、描き直しの番号を1つ進める。古い番号の描画の結果は使わない。
3. **粗い下描き:** 解像度を4分の1、アンチエイリアスなし（`aa_level` 1）で全体を描き、全部そろったら引き伸ばしてキャンバス全体に描く（`scale: 0.25`、`clear: false`）。
4. **本描き:** 下描きが終わったら、元の解像度とアンチエイリアス（`aa_level` 3、今の既定値）で描き、ブロックが届くたびに上書きする（`clear: false`）。途中で黒い画面に戻ることはない。
5. **キャンバスの解像度:** `floor(表示の大きさ × min(devicePixelRatio, 2))`。iPhone（3倍）ではわずかに粗くなるが、描画時間を約半分にできる。
6. **c の変更:** 画像の形そのものが変わるので、プレビューの変形はしない。今の画像を残したまま 3 と 4 で描き直す。

## 8. 想定外の操作や状況への対応

- 入力欄:
  - 数値として読めない値は適用しない。その欄を赤く示し、Enter や `Go` を押しても表示を動かさない。
  - 範囲外の値は制限の内側の値に直して適用し、直した値を欄に表示する。
- 拡大の上限に着いたら、それ以上は拡大しない。拡大率の表示に `(max)` を付ける。
- 描画の途中で次の操作、ページの移動、キャンバスの大きさの変更があったら、古い描画を取り消す（今の `cancelGroup` と、7章の描き直しの番号を使う）。
- ページを離れるときは、描画、タイマー、イベントの登録をすべて片付ける。
- MathJax を読み込めないときは、今と同じく数式の元の文字列がそのまま表示される。
- 一部のブロックの描画に失敗したときは、今と同じくコンソールに警告を出し、残りのブロックは描く。

## 9. テスト

1. **単体テスト（`www/src/utils/viewMath.test.ts`）:** Node に入っているテスト機能（`node --test`）で実行し、新しいパッケージは追加しない。テストのファイルは `node:test` を使うため、`tsc` の対象からは外す（`viewMath.ts` 自体は今までどおり `tsc` で型を確かめる）。確かめること:
   - `zoomAt` の前後で、固定した点の複素数が変わらない
   - `panBy` の向きと量（画像が指と同じ向きに動く）
   - 縮小、移動、拡大の制限（制限を越える倍率は、固定点を保ったまま制限ちょうどになる）
   - 拡大の上限で、1ピクセルの幅が `K × ulp` 以上
   - `autoMaxIter` の値（×1、×100万、×1兆）と上限の 50,000
   - `previewTransform` の位置と大きさが `zoomAt`、`panBy` と食い違わない
   - 6章の初期範囲が正方形であること。Burning Ship と Celtic が今と完全に同じ値であること
   - 数値の表示と読み取り（指数表記、不正な文字列）
2. **CI:** `Test` ワークフローとデプロイのワークフローの両方で、`node --test` を実行する。
3. **Rust のテスト:** 今の20件がそのまま通る（Rust は変更しない）。
4. **ブラウザでの確認:** Chromium を Playwright で自動操作するスクリプトで確かめる。スクリプトは作業用のフォルダに置き、リポジトリには入れない。
   - ギャラリー: Burning Ship と Celtic の画像が今とピクセル単位で同じこと。Mandelbrot と Julia が正しい縦横比になったこと。
   - 各ページで次の操作をし、拡大率と中心座標の表示が期待どおりに変わること。
     - ホイール、ドラッグ、ダブルクリック
     - ピンチとダブルタップ（タッチ操作を再現した iPhone サイズの画面で）
     - `+`、`−`、`Reset`
     - 入力欄からの移動と、不正な入力
     - `Auto` の反復回数
     - Julia の c の変更（画像と、数式の TeX の文字列が変わること）
   - 古い描画が残らないこと: 速い操作を続けたあとの最終的な画像が、同じ範囲を新しく描いた画像とピクセル単位で一致すること。
   - 時間: 粗い下描きと本描きにかかる時間を、いくつかの拡大率で測る。
   - コンソールにエラーが出ないこと。
5. **この環境で確かめられないこと:** 実機の iPhone（Safari）での操作感と、MathJax で表示された数式の見た目。公開後に実機で確かめてもらう。
